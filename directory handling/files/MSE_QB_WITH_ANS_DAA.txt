Q1. WHAT IS AN ALGORITHM? GIVE ITS CHARACTERISTICS.

Answer:

Definition:
An algorithm is a finite sequence of well-defined and ordered
instructions used to solve a particular problem or perform a
computation.

In simple words, an algorithm tells us:
Input → Processing Steps → Output

Example:
Algorithm to find the sum of two numbers:

Step 1: Start
Step 2: Read A and B
Step 3: S = A + B
Step 4: Display S
Step 5: Stop

Characteristics of an Algorithm:

1. Input:
   An algorithm accepts zero or more inputs.

2. Output:
   An algorithm produces at least one output.

3. Definiteness:
   Every instruction must be clear and unambiguous.

4. Finiteness:
   The algorithm must terminate after a finite number of steps.

5. Effectiveness:
   Each instruction should be simple and executable in finite time.

6. Correctness:
   The algorithm should produce the correct result for valid input.

7. Generality:
   An algorithm should solve all instances of a particular problem.

Conclusion:
Thus, an algorithm is a step-by-step finite procedure that converts
input into the required output.

Keywords:
Input, Output, Definiteness, Finiteness, Effectiveness, Correctness.

Q2. EXPLAIN DIFFERENT ASYMPTOTIC NOTATIONS.
============================================================

Answer:

Asymptotic notations are mathematical tools used to describe the
growth rate of an algorithm's time or space complexity as the input
size n becomes very large.

The main asymptotic notations are:

1. Big-O Notation O

Big-O notation represents the upper bound or worst-case growth of
an algorithm.

Definition:
f(n) = O(g(n)) if there exist positive constants c and n0 such that:

0 ≤ f(n) ≤ c.g(n), for all n ≥ n0

Example:
3n² + 2n + 1 = O(n²)

This is because, for large n, the term n² dominates the other terms.

Example:
Linear Search worst case = O(n)


2. Big-Omega Notation Ω

Big-Omega notation represents the lower bound or best-case growth of
an algorithm.

Definition:
f(n) = Ω(g(n)) if there exist positive constants c and n0 such that:

0 ≤ c.g(n) ≤ f(n), for all n ≥ n0

Example:
3n² + 2n + 1 = Ω(n²)

Example:
Linear Search best case = Ω(1)


3. Big-Theta Notation Θ

Theta notation represents a tight bound.

It means that the function grows at the same order as another function.

Definition:
f(n) = Θ(g(n)) if there exist positive constants c1, c2 and n0 such
that:

0 ≤ c1.g(n) ≤ f(n) ≤ c2.g(n)

for all n ≥ n0.

Example:
3n² + 2n + 1 = Θ(n²)


Comparison:

O(g(n))  → Upper bound
Ω(g(n))  → Lower bound
Θ(g(n))  → Tight bound

Conclusion:
Asymptotic notations help us compare algorithms without depending on
specific hardware or programming language.

============================================================

Answer:

The efficiency of an algorithm is evaluated using performance
analysis and performance measurement.

1. Performance Analysis:

Performance analysis is a theoretical method of determining the
efficiency of an algorithm.

It mainly considers:

a) Time Complexity:
The amount of time required by an algorithm as a function of input
size n.

b) Space Complexity:
The amount of memory required by an algorithm as a function of input
size n.

The analysis is generally independent of:
- Computer hardware
- Programming language
- Operating system

Example:
Binary Search has time complexity:

Best case  = O(1)
Worst case = O(log n)


2. Performance Measurement:

Performance measurement is an experimental method of evaluating an
algorithm by actually implementing and executing it.

It measures:
- Actual execution time
- Memory used
- CPU utilization

The result may depend on:
- Processor speed
- Programming language
- Compiler
- Operating system
- Input data


Difference:

Performance Analysis:
- Theoretical
- Machine independent
- Uses mathematical analysis
- Gives complexity

Performance Measurement:
- Experimental
- Machine dependent
- Requires implementation
- Gives actual execution time


Conclusion:
Performance analysis predicts the efficiency of an algorithm
theoretically, whereas performance measurement evaluates its actual
performance on a computer system.

Q4. EXPLAIN TOWER OF HANOI PROBLEM AND ANALYZE ITS COMPLEXITY.
============================================================

Answer:

Tower of Hanoi is a classical recursive problem consisting of:

- Three rods
- n disks of different sizes

Initially, all disks are placed on the source rod in increasing size
from top to bottom.

Objective:
Move all disks from the source rod to the destination rod using an
auxiliary rod.

Rules:

1. Only one disk can be moved at a time.
2. A larger disk cannot be placed on a smaller disk.
3. Only the top disk of a rod can be moved.


Algorithm:

TOH(n, Source, Auxiliary, Destination)

If n = 1:
    Move disk 1 from Source to Destination

Otherwise:
    Move n-1 disks from Source to Auxiliary
    Move nth disk from Source to Destination
    Move n-1 disks from Auxiliary to Destination


Pseudo Code:

TOH(n, S, A, D)
{
    if(n == 1)
    {
        print "Move disk from S to D"
        return
    }

    TOH(n-1, S, D, A)

    print "Move disk", n, "from S to D"

    TOH(n-1, A, S, D)
}


Recurrence Relation:

T(n) = 2T(n-1) + 1

Where:
2T(n-1) represents moving n-1 disks two times.
1 represents moving the largest disk.

Solving:

T(n) = 2ⁿ - 1

Therefore:

Time Complexity = O(2ⁿ)

Space Complexity = O(n)
because recursive calls use stack space.

Conclusion:
Tower of Hanoi is a recursive problem with exponential time
complexity O(2ⁿ).

Q5. COMPARE THE COMPLEXITIES:
n, log n, n log n, n², n³ AND 2ⁿ
============================================================

Answer:

The order of growth from smallest to largest is:

log n < n < n log n < n² < n³ < 2ⁿ

Explanation:

1. O(log n):
   Logarithmic growth.
   Example: Binary Search.

2. O(n):
   Linear growth.
   Example: Linear Search.

3. O(n log n):
   Linear-logarithmic growth.
   Example: Merge Sort.

4. O(n²):
   Quadratic growth.
   Example: Selection Sort.

5. O(n³):
   Cubic growth.
   Example: Some matrix algorithms.

6. O(2ⁿ):
   Exponential growth.
   Example: Tower of Hanoi.


Growth Order:

Best --------------------------------------> Worst

log n → n → n log n → n² → n³ → 2ⁿ


Example for large input:
As n increases, exponential algorithms become extremely slow compared
to polynomial algorithms.

Conclusion:
Algorithms having logarithmic or linear complexity are generally more
efficient than quadratic, cubic and exponential algorithms.

Q6. WRITE RECURSIVE AND ITERATIVE ALGORITHMS TO COMPUTE n!.
============================================================

Answer:

Factorial of n is defined as:

n! = n × (n-1) × (n-2) × ... × 1

Also:

0! = 1


A) Recursive Algorithm:

Factorial(n)
{
    if(n == 0 || n == 1)
        return 1;

    return n × Factorial(n-1);
}


Example:

Factorial(5)

= 5 × Factorial(4)
= 5 × 4 × Factorial(3)
= 5 × 4 × 3 × 2 × 1
= 120


Time Complexity:

T(n) = T(n-1) + O(1)

Therefore:

Time Complexity = O(n)

Space Complexity = O(n)
due to recursive stack.


B) Iterative Algorithm:

Factorial(n)
{
    fact = 1;

    for(i = 1; i <= n; i++)
        fact = fact × i;

    return fact;
}


Example:

n = 5

fact = 1 × 2 × 3 × 4 × 5
     = 120


Complexity:

Time Complexity = O(n)

Space Complexity = O(1)


Conclusion:

Both algorithms require O(n) time.

Recursive method:
Easy to understand but uses extra stack memory.

Iterative method:
Uses constant extra space.

Q7. WRITE RECURSIVE AND ITERATIVE ALGORITHMS TO COMPUTE
FIBONACCI NUMBERS.
============================================================

Answer:

The Fibonacci sequence is:

0, 1, 1, 2, 3, 5, 8, 13, ...

The recurrence relation is:

F(n) = F(n-1) + F(n-2)

with:

F(0) = 0
F(1) = 1


A) Recursive Algorithm:

Fibonacci(n)
{
    if(n == 0)
        return 0;

    if(n == 1)
        return 1;

    return Fibonacci(n-1) + Fibonacci(n-2);
}


Example:

F(5)

= F(4) + F(3)
= 3 + 2
= 5


Complexity:

The recursive algorithm repeatedly calculates the same values.

Time Complexity ≈ O(2ⁿ)

Space Complexity = O(n)


B) Iterative Algorithm:

Fibonacci(n)
{
    a = 0;
    b = 1;

    if(n == 0)
        return 0;

    for(i = 2; i <= n; i++)
    {
        c = a + b;
        a = b;
        b = c;
    }

    return b;
}


Example:

a = 0
b = 1

Next values:

1, 2, 3, 5

Therefore:

F(5) = 5


Complexity:

Time Complexity = O(n)

Space Complexity = O(1)


Conclusion:

The iterative Fibonacci algorithm is more efficient than the simple
recursive algorithm because it avoids repeated calculations.

Q8. EXPLAIN DIVIDE AND CONQUER ALGORITHM WITH RECURRENCE RELATION.
============================================================

Answer:

Divide and Conquer is an algorithm design technique in which a large
problem is divided into smaller subproblems.

The solutions of smaller subproblems are then combined to obtain the
solution of the original problem.


Three Steps:

1. Divide:
   Divide the problem into smaller subproblems.

2. Conquer:
   Solve each subproblem recursively.

3. Combine:
   Combine the solutions of subproblems.


General Form:

Divide
   ↓
Solve smaller subproblems
   ↓
Combine solutions


General Algorithm:

DivideAndConquer(P)
{
    if(P is small)
        solve P directly;
    else
    {
        divide P into smaller subproblems;
        solve each subproblem recursively;
        combine the solutions;
    }
}


Recurrence Relation:

If a problem of size n is divided into a subproblems, each of size n/b,
then:

T(n) = aT(n/b) + f(n)

Where:

a = Number of subproblems
n/b = Size of each subproblem
f(n) = Cost of dividing and combining


Examples:

Binary Search:
T(n) = T(n/2) + O(1)

Merge Sort:
T(n) = 2T(n/2) + O(n)

Quick Sort:
Average:
T(n) = 2T(n/2) + O(n)


Applications:
- Binary Search
- Merge Sort
- Quick Sort
- Maximum and Minimum

Conclusion:
Divide and Conquer solves complex problems efficiently by breaking them
into smaller and manageable subproblems.

Q10. EXPLAIN RECURSIVE BINARY SEARCH WITH AN EXAMPLE.
============================================================

Answer:

Binary Search is a Divide and Conquer searching algorithm used to
search an element in a sorted array.

It repeatedly divides the search interval into two halves.


Algorithm:

BinarySearch(A, low, high, key)
{
    if(low > high)
        return -1;

    mid = (low + high) / 2;

    if(A[mid] == key)
        return mid;

    else if(key < A[mid])
        return BinarySearch(A, low, mid-1, key);

    else
        return BinarySearch(A, mid+1, high, key);
}


Example:

Array:

10, 20, 30, 40, 50, 60, 70

Find key = 50

Step 1:

low = 0
high = 6

mid = (0 + 6)/2 = 3

A[3] = 40

Since 50 > 40, search right half.


Step 2:

low = 4
high = 6

mid = (4 + 6)/2 = 5

A[5] = 60

Since 50 < 60, search left half.


Step 3:

low = 4
high = 4

mid = 4

A[4] = 50

Therefore, key is found.


Recurrence:

T(n) = T(n/2) + O(1)


Time Complexity:

Best Case = O(1)

Worst Case = O(log n)

Space Complexity:

Recursive Binary Search = O(log n)


Conclusion:

Binary Search is highly efficient for searching in sorted data.

Q11. EXPLAIN MERGE SORT WITH EXAMPLE AND COMPLEXITY.
============================================================

Answer:

Merge Sort is a Divide and Conquer sorting algorithm.

It divides the array into two halves, recursively sorts both halves,
and then merges them.


Algorithm:

MergeSort(A, low, high)
{
    if(low < high)
    {
        mid = (low + high)/2;

        MergeSort(A, low, mid);
        MergeSort(A, mid+1, high);

        Merge(A, low, mid, high);
    }
}


Example:

Array:

38, 27, 43, 3, 9, 82, 10


Divide:

[38,27,43,3] [9,82,10]

Further divide until single elements:

[38] [27] [43] [3] [9] [82] [10]


Merge:

[27,38]
[3,43]

Then:

[3,27,38,43]

Similarly:

[9,10,82]


Final Merge:

[3,27,38,43] + [9,10,82]

Final Sorted Array:

3, 9, 10, 27, 38, 43, 82


Complexity Analysis:

The array is divided into two parts:

2T(n/2)

Merging requires:

O(n)

Therefore:

T(n) = 2T(n/2) + O(n)

Using recurrence analysis:

T(n) = O(n log n)


Best Case = O(n log n)
Average Case = O(n log n)
Worst Case = O(n log n)

Space Complexity = O(n)


Conclusion:

Merge Sort guarantees O(n log n) time complexity but requires
additional memory for merging.

Q12. EXPLAIN QUICK SORT WITH EXAMPLE AND COMPLEXITY.
============================================================

Answer:

Quick Sort is a Divide and Conquer sorting algorithm.

It selects an element called a pivot and partitions the remaining
elements into:

- Elements smaller than the pivot
- Elements greater than the pivot

The subarrays are then sorted recursively.


Algorithm:

QuickSort(A, low, high)
{
    if(low < high)
    {
        p = Partition(A, low, high);

        QuickSort(A, low, p-1);
        QuickSort(A, p+1, high);
    }
}


Example:

Array:

40, 20, 60, 10, 50, 30

Choose pivot = 40

Partition:

Smaller than 40:
20, 10, 30

Pivot:
40

Greater than 40:
60, 50


Therefore:

20, 10, 30 | 40 | 60, 50

Sort subarrays:

10, 20, 30 | 40 | 50, 60


Final Answer:

10, 20, 30, 40, 50, 60


Complexity:

Best Case:

Balanced partition:

T(n) = 2T(n/2) + O(n)

Therefore:

O(n log n)


Average Case:

O(n log n)


Worst Case:

When partition is highly unbalanced:

T(n) = T(n-1) + O(n)

Therefore:

O(n²)


Space Complexity:

Average = O(log n) for recursion


Conclusion:

Quick Sort is very efficient in practice. Its average complexity is
O(n log n), although the worst-case complexity is O(n²).

Q13. EXPLAIN DC SELECTION ALGORITHM / k-th SMALLEST ELEMENT.
============================================================

Answer:

The selection problem is used to find the k-th smallest element from a
set of n elements.

Example:

A = {7, 2, 9, 4, 1}

Sorted order:

1, 2, 4, 7, 9

If k = 3:

The 3rd smallest element is 4.


Using Divide and Conquer:

1. Select a pivot.
2. Partition the elements into:
   - Smaller elements
   - Pivot
   - Larger elements
3. Determine the rank of the pivot.
4. If pivot rank = k, return pivot.
5. If k is smaller, search left part.
6. Otherwise search right part.


Algorithm:

Select(A, low, high, k)
{
    partition the array around a pivot;

    p = position of pivot;

    if(p == k)
        return A[p];

    else if(k < p)
        search left subarray;

    else
        search right subarray;
}


Complexity:

Average Case = O(n)

Worst Case = O(n²) for poor pivot selection.

Conclusion:

The Divide and Conquer selection method finds the required k-th
smallest element without completely sorting the array.

Q14. EXPLAIN SELECTION SORT AND SHOW ITS COMPLEXITY IS O(n²).
============================================================

Note:
Selection Sort appears in your QB, although it is not explicitly named
in the Unit 1 syllabus you shared.

Answer:

Selection Sort repeatedly selects the smallest element from the
unsorted part of the array and places it in the correct position.


Algorithm:

SelectionSort(A, n)
{
    for(i = 0; i < n-1; i++)
    {
        min = i;

        for(j = i+1; j < n; j++)
        {
            if(A[j] < A[min])
                min = j;
        }

        swap(A[i], A[min]);
    }
}


Example:

Array:

64, 25, 12, 22, 11

Pass 1:

11, 25, 12, 22, 64

Pass 2:

11, 12, 25, 22, 64

Pass 3:

11, 12, 22, 25, 64

Pass 4:

11, 12, 22, 25, 64


Number of comparisons:

(n-1) + (n-2) + ... + 1

= n(n-1)/2

Therefore:

Time Complexity = O(n²)

Best Case = O(n²)
Average Case = O(n²)
Worst Case = O(n²)

Space Complexity = O(1)

Binary Search      → O(log n)

Max-Min            → O(n)

Divide and Conquer algorithms are analyzed mainly by recurrence

Q1. WRITE A SHORT NOTE ON THE GREEDY METHOD / GENERAL METHOD.
============================================================

Answer:

The Greedy Method is an algorithm design technique in which a solution
is constructed step by step by making the best possible choice at each
stage.

The choice made at a particular stage is called a local optimum.
The objective is to obtain an overall optimal solution.

General Strategy:

1. Start with an empty solution.
2. Select the best available candidate.
3. Check whether the candidate gives a feasible solution.
4. If feasible, include it in the solution.
5. Repeat until the solution is complete.

General Algorithm:

Greedy(A)
{
    Solution = empty;

    while(Solution is not complete)
    {
        Select the best candidate;

        if(candidate is feasible)
            add candidate to Solution;
    }

    return Solution;
}

Characteristics:

1. Greedy Choice Property:
   A globally optimal solution can be obtained by making locally
   optimal choices.

2. Optimal Substructure:
   An optimal solution contains optimal solutions to its subproblems.

Advantages:
- Simple to understand.
- Usually easy to implement.
- Often efficient.
- Requires less computation.

Applications:
- Fractional Knapsack
- Job Sequencing with Deadlines
- Prim's Algorithm
- Kruskal's Algorithm
- Dijkstra's Algorithm
- Optimal Merge Pattern

Conclusion:
Thus, the Greedy Method makes the best local choice at every step
with the aim of obtaining a globally optimal solution.

Q2. FIND AN OPTIMAL SOLUTION TO A KNAPSACK INSTANCE.
============================================================

Answer:

The Knapsack Problem is solved using the Greedy Method when fractional
items are allowed.

Given:

Profit = Pi
Weight = Wi

The selection criterion is:

Profit / Weight ratio = Pi / Wi

Steps:

1. Calculate Pi/Wi for every item.
2. Arrange items in decreasing order of Pi/Wi.
3. Select items having the highest ratio first.
4. If an entire item cannot fit, take the required fraction of it.

Example:

Let the knapsack capacity be W = 50.

Item       Profit(P)       Weight(W)       P/W
------------------------------------------------
1             60               10            6
2            100               20            5
3            120               30            4

Arrange in decreasing P/W ratio:

Item 1 → Item 2 → Item 3

Step 1:
Take Item 1 completely.

Weight = 10
Profit = 60

Remaining capacity = 40

Step 2:
Take Item 2 completely.

Weight = 20
Profit = 100

Remaining capacity = 20

Step 3:
Item 3 has weight 30, but only 20 capacity remains.

Take 20/30 = 2/3 of Item 3.

Profit obtained:

(2/3) × 120 = 80

Therefore:

Total Weight = 50

Total Profit = 60 + 100 + 80
             = 240

Optimal Profit = 240

Conclusion:
For Fractional Knapsack, selecting items according to decreasing
Profit/Weight ratio gives the optimal solution.

Q3. PROVE THAT GREEDY METHOD GENERATES AN OPTIMAL SOLUTION
FOR THE KNAPSACK PROBLEM.
============================================================

Answer:

Consider n items having:

Profit: P1, P2, ..., Pn

Weight: W1, W2, ..., Wn

Assume that the items are arranged such that:

P1/W1 ≥ P2/W2 ≥ ... ≥ Pn/Wn

The ratio Pi/Wi represents the profit obtained per unit weight.

Greedy Strategy:

At each step, select the item having the maximum Profit/Weight ratio.

Suppose an optimal solution does not select the item with the highest
ratio first and instead selects an item having a lower ratio.

Let:

P1/W1 > P2/W2

Then, for the same amount of weight, Item 1 produces more profit than
Item 2.

Therefore, replacing some weight of Item 2 with Item 1 increases or
maintains the total profit.

Hence, an optimal solution can always be transformed into one that
contains the highest Profit/Weight ratio item first.

Applying the same argument repeatedly to the remaining capacity,
the items are selected in decreasing order of Profit/Weight ratio.

Therefore:

If

P1/W1 ≥ P2/W2 ≥ ... ≥ Pn/Wn

then the Greedy Method produces an optimal solution for the
Fractional Knapsack Problem.

Important Note:

This proof is valid for the Fractional Knapsack Problem, where an item
can be divided.

It is not generally valid for the 0/1 Knapsack Problem.

Q5. GIVE AN ALGORITHM TO FIND MINIMUM COST SPANNING TREE.
============================================================

Answer:

A Minimum Cost Spanning Tree (MCST) is a spanning tree whose total
edge weight is minimum among all possible spanning trees.

A weighted connected graph may have several spanning trees, but the
MCST has minimum total cost.

General Approach:

1. Start with a graph having all vertices.
2. Select edges according to minimum weight.
3. Do not select an edge if it creates a cycle.
4. Continue until n - 1 edges are selected.

Algorithms used to find MCST:

1. Prim's Algorithm
2. Kruskal's Algorithm

Basic Algorithm:

MCST(G)
{
    T = empty set;

    while(T contains fewer than n-1 edges)
    {
        select a minimum cost edge;

        if(adding the edge does not form a cycle)
            add edge to T;
    }

    return T;
}

Cost of MCST:

Cost(T) = Sum of weights of all selected edges

Conclusion:

The objective of MCST algorithms is to connect every vertex with
minimum possible total edge cost.

Answer:

The Single Source Shortest Path problem finds the shortest path from
one source vertex to all other vertices in a weighted graph.

A commonly used Greedy Algorithm is Dijkstra's Algorithm.

Condition:

Dijkstra's Algorithm works correctly when edge weights are
non-negative.

Algorithm:

1. Assign distance 0 to the source vertex.
2. Assign infinity to all other vertices.
3. Select the unvisited vertex having minimum distance.
4. Mark it as visited.
5. Update distances of its adjacent vertices.
6. Repeat until all vertices are visited.

Relaxation:

If:

distance[u] + weight(u,v) < distance[v]

Then update:

distance[v] =
distance[u] + weight(u,v)


Pseudo Code:

Dijkstra(G, source)
{
    Set distance[source] = 0;

    Set distance of all other vertices = ∞;

    while(unvisited vertices exist)
    {
        u = unvisited vertex with minimum distance;

        mark u as visited;

        for each neighbour v of u
        {
            if(distance[u] + weight(u,v) < distance[v])
            {
                distance[v] =
                distance[u] + weight(u,v);
            }
        }
    }
}

Example:

Suppose:

A → B = 4
A → C = 1
C → B = 2
B → D = 1
C → D = 5

Source = A

Shortest distances:

A → C = 1

A → C → B = 1 + 2 = 3

A → C → B → D = 1 + 2 + 1 = 4

Therefore:

Vertex       Distance
----------------------
A              0
B              3
C              1
D              4

Conclusion:

The Single Source Shortest Path algorithm finds minimum distances from
one source to all other vertices.

Q1. EXPLAIN THE GENERAL METHOD OF BACKTRACKING.
============================================================

Answer:

Backtracking is an algorithm design technique used to solve problems
by constructing a solution step by step.

At each step, a possible choice is made. If the choice does not lead
to a valid solution, the algorithm goes back and tries another choice.

This process is called Backtracking.

Simple Idea:

Choose → Check → Continue
          ↓
       Invalid?
          ↓
        Go Back

Backtracking generally uses a state-space tree.

General Algorithm:

Backtrack(k)
{
    if(k represents a complete solution)
    {
        output solution;
        return;
    }

    for(each possible choice)
    {
        make a choice;

        if(choice is promising)
            Backtrack(k + 1);

        undo the choice;
    }
}

Important Terms:

1. State Space Tree:
   A tree representing all possible solutions.

2. Promising Node:
   A node that may lead to a valid solution.

3. Non-promising Node:
   A node that cannot lead to a valid solution.

4. Backtracking:
   Returning to a previous node when the current choice fails.

Applications:

- N-Queen Problem
- Sum of Subsets
- 0/1 Knapsack
- Hamiltonian Cycle
- Graph Coloring

Conclusion:

Backtracking systematically searches for a solution by exploring
possible choices and abandoning invalid paths as early as possible.

Q9. EXPLAIN LIVE NODE, E-NODE, DEAD NODE AND BOUNDING FUNCTION.
============================================================

Answer:

These terms are generally associated with state-space tree search
and Branch and Bound. They appear in your Question Bank.

1. Live Node:

A live node is a node that has been generated but has not yet been
expanded.

It is still a candidate for further exploration.

Example:

A partially constructed solution waiting to be explored.


2. E-Node:

E-Node means Expansion Node.

It is the live node currently selected for expansion.

When an E-Node is expanded, its child nodes are generated.


3. Dead Node:

A dead node is a node that will not be expanded further.

A node may become dead when:

- It represents a complete solution.
- It cannot lead to a solution.
- Its branch is pruned.


4. Bounding Function:

A bounding function is used to estimate the best possible value that
can be obtained from a node.

It helps decide whether the node should be explored further.

If the bound shows that the node cannot produce a better solution,
the branch is discarded.


Example:

For a maximization problem:

If:

Upper Bound of current node
<
Current Best Solution

then the node can be pruned.


Simple Relationship:

Live Node
    ↓
Selected for expansion
    ↓
E-Node
    ↓
Generate child nodes
    ↓
Useful nodes → Live Nodes

Unpromising/Completed nodes → Dead Nodes


Conclusion:

These concepts help reduce unnecessary exploration of the state-space
tree and improve the efficiency of search algorithms.
